# Phase 1 input: every test method name, before the prose pass

One `<file>\t<name>` per line, all 388, snapshotted at the commit that
completed Task 3.

## Why this exists

The identifier inventory deliberately excluded `test_*` methods, on the
assumption that 388 names each used once would be noise. That was wrong: the
large majority are Portuguese, they are identifiers, and they are what `-v`
test output prints — the most-read English surface in the repository after the
CLI.

Neither Phase 1 acceptance criterion sees them. Zero contain an accented
character, so the accent check is blind to all 388, and none is a Portuguese
function word. This is the fifth verification gap of this project with the
same shape: thorough about the categories its author imagined.

## What Task 8 must do

Rename every Portuguese one. A test name is a sentence describing what the
test proves, so this is prose translation, not symbol substitution — carry
the meaning:

- `test_lista_e_rejeitada` -> `test_list_is_rejected`
- `test_avisa_quando_tem_travessao` -> `test_warns_on_em_dash`
- `test_nao_expande_pro_em_locucao` -> the guard it names is DELETED by Task 5,
  so this test goes with it rather than being translated

Renaming is safe: no test method is referenced by name as a string anywhere,
no decorator is keyed on one, and `subTest` uses keyword arguments. Verified
before this file was written. The suite count must stay at 388 except where a
task explicitly deletes a test and says so.
